# 변경 제약을 먼저 명시하기

## 상황

변경하면 안 되는 인터페이스, 데이터, 라이브러리 또는 승인 절차가 있는 작업에 적용함.

## 방법

유지할 항목, 변경 금지 범위, 허용되지 않는 작업, 사전 확인이 필요한 작업을 요청문에 명시함.

## 예시

```text
API 형식은 바꾸지 말고 TypeScript 파일만 수정해 주세요.
의존성 추가가 필요하면 변경 전에 확인해 주세요.
```

## 주의점

모든 과정을 과도하게 지정하기보다 결과에 직접 영향을 주는 제약을 우선 작성함. 모호한 제약은 검토 기준으로 사용하기 어려우므로 구체화 필요함.
